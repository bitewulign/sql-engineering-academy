## Key Concepts to Understand Deeply

### DECIMAL vs FLOAT — Why It Matters for Money

**Problem with FLOAT:**
```
0.1 + 0.2 = 0.30000000000000004  (floating-point arithmetic)
```
Financial calculations require exact arithmetic. Even a penny rounding error compounded across millions of rows becomes a serious problem.

**DECIMAL(p, s)** stores numbers as exact scaled integers internally — no floating-point rounding ever occurs. Use `DECIMAL(10,2)` for currency, `DECIMAL(3,2)` for GPA, `DECIMAL(5,4)` for interest rates.

### utf8mb4 vs utf8 in MySQL

MySQL's `utf8` character set was capped at 3 bytes, which covers the Basic Multilingual Plane but excludes emoji (which require 4 bytes in UTF-8 encoding). `utf8mb4` is genuine UTF-8 supporting the full Unicode range including emoji. Always use `utf8mb4` in new MySQL databases.

### SCOPE_IDENTITY() vs @@IDENTITY

| Function | Returns |
|----------|---------|
| `SCOPE_IDENTITY()` | Last identity generated **in the current scope** (your batch or stored procedure) |
| `@@IDENTITY` | Last identity generated **in the current session** — including identities generated by triggers on other tables |

If a trigger on `students` inserts into an `audit_log` table that also has an identity column, `@@IDENTITY` returns the audit log's identity, not the students identity. `SCOPE_IDENTITY()` always returns the students identity in that case. Prefer `SCOPE_IDENTITY()`.

### GENERATED ALWAYS AS IDENTITY vs SERIAL (PostgreSQL)

Both create auto-incrementing columns, but:

- `SERIAL` is a PostgreSQL-specific shorthand that creates a sequence and sets a default — the column is still a plain `INT` and can be overridden by supplying a value in INSERT.
- `GENERATED ALWAYS AS IDENTITY` (SQL:2003 standard) prevents inserting explicit values unless you specify `OVERRIDING SYSTEM VALUE`. It makes the auto-increment behavior clear and enforced.

New code should prefer `GENERATED ALWAYS AS IDENTITY`.

## Module 02 Key Terms Quick Reference

| Term | Definition | Platform note |
|------|------------|---------------|
| DDL | Data Definition Language — CREATE, ALTER, DROP | Same across platforms |
| DML | Data Manipulation Language — INSERT, UPDATE, DELETE | Same across platforms |
| Constraint | A rule enforced at the database layer | Naming convention: `pk_`, `uq_`, `chk_`, `fk_`, `df_` |
| AUTO_INCREMENT | MySQL's keyword for auto-incrementing PKs | MySQL only |
| SERIAL | PostgreSQL shorthand for sequence + integer column | PostgreSQL only |
| GENERATED ALWAYS AS IDENTITY | SQL standard identity column | PostgreSQL 10+; SQL Server uses IDENTITY(1,1) |
| IDENTITY(seed, increment) | SQL Server auto-increment | SQL Server only |
| RETURNING | PostgreSQL clause to get back row data from DML | PostgreSQL only |
| OUTPUT INSERTED | SQL Server equivalent of RETURNING on INSERT/UPDATE | SQL Server only |
| OUTPUT DELETED | SQL Server equivalent of RETURNING on DELETE | SQL Server only |
| SCOPE_IDENTITY() | SQL Server function for last inserted identity value | SQL Server only |
| LAST_INSERT_ID() | MySQL function for last auto-increment value | MySQL only |
| TRUNCATE | Removes all rows; faster than DELETE; resets identity | Behavior differs: see notes |
| NVARCHAR | SQL Server Unicode variable-length text type | SQL Server only — use for all text |
| utf8mb4 | MySQL's full UTF-8 character set (4-byte) | MySQL only — always use over `utf8` |
| TIMESTAMPTZ | PostgreSQL timestamp with time zone | PostgreSQL only |
| DATETIME2 | SQL Server high-precision datetime | SQL Server — preferred over DATETIME |
| ENGINE=InnoDB | MySQL storage engine that enforces FK constraints | MySQL only — required for FKs |
